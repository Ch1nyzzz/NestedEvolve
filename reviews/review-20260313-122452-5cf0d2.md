## High Severity

### 1. `noa/core/protocol.py:461`
- Severity: high
- Category: Diff
- Description: `OptimizationBudget.reached_limit()` now returns `self.step_count >= self.max_steps` only. The main stop path in `noa/unified_agent.py:872-890` relies on this method, so the changed code no longer stops when `evals_used >= max_evals` or `llm_calls_used >= max_llm_calls`. That allows optimization runs to exceed configured evaluation and API-call budgets until they hit step count or timeout.
- Suggested fix: Restore `max_evals` and `max_llm_calls` enforcement inside `reached_limit()` or add equivalent checks in `_should_stop()`. Add a regression test that proves both limits terminate the loop.

### 2. `noa/subprocess_runner.py:151`
- Severity: high
- Category: Diff
- Description: The subprocess path loads `train_pool` and `test_set` but drops `val_set` entirely. `noa/orchestrator.py:70-78` serializes `train_pool`, `val_set`, and `test_set`, and `noa/orchestrator.py:113-134` passes `val_set` into the top-level `NOptimizer`, but `run_layer_subprocess()` accepts only `train_pool_pickle_path` and `test_set_pickle_path`. The nested mini-L1 subprocess call in `noa/unified_agent.py:664-702` therefore loses validation data, so the new validation-baseline and commit logic is bypassed in subprocess-driven runs.
- Suggested fix: Thread `val_set_pickle_path` through `run_layer_subprocess()` and `_run_mini_l1_subprocess()`, load it in the child process, and pass `val_set=...` into `NOptimizer`. Add a subprocess regression test that asserts validation data reaches the child optimizer.
