# Consolidated Review

## Critical

- File: `noa/unified_agent.py`
- Line: `489`
- Severity: critical
- Category: Diff, Holistic
- Description: The automatic post-loop spawn fallback still checks `result.get("accepted")` and `result.get("spawn_restart")`, but `_tool_spawn_sublayer()` now returns `child_accepted` and `noa_modified` at line 1952. When L2 successfully modifies `noa/`, `_spawn_noa_modified` is never set, so the expected L1 restart can be skipped and framework changes can be silently dropped.
- Suggested fix: Update the fallback condition to use the current return contract, for example `result.get("child_accepted", 0) > 0 or result.get("noa_modified")`, and add a regression test that exercises the auto-spawn path.

## High

- File: `noa/core/protocol.py`
- Line: `461`
- Severity: high
- Category: Diff
- Description: `OptimizationBudget.reached_limit()` no longer enforces `max_llm_calls`, even though the rest of the system still increments `llm_calls_used` and passes `max_llm_calls` through configuration. Runs can now exceed the configured LLM-call cap until another stop condition happens to fire.
- Suggested fix: Restore the `self.llm_calls_used >= self.max_llm_calls` branch in `reached_limit()`, or remove the unused setting and document that wall-clock timeout is now the only LLM budget.

- File: `noa/engine.py`
- Line: `164`
- Severity: high
- Category: Holistic
- Description: `NOptimizer.run()` writes `status="running"` back into shared runtime state immediately before returning. Callers that read `current_run.json` after the optimizer finishes but before an outer orchestrator updates it will observe a stale running state.
- Suggested fix: Remove the trailing `update_current_run(...)` call or set a terminal status there instead of restoring `running`.

## Medium

- Severity: medium
- Category: Diff
