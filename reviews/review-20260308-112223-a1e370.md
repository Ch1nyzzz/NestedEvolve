# Consolidated Review

## High

1. File: `noa/unified_agent.py:1177`
   Severity: high
   Category: Diff
   Description: `eval_candidate()` adds every evaluated candidate to `_top_candidates` before the acceptance policy runs. `accept_candidate()` then checks `not in_top and cand_score <= baseline`, so once a candidate has been evaluated it can bypass the baseline gate, survive into the top-K pool, and reach final held-out evaluation without ever being explicitly accepted.
   Suggested fix: Keep evaluation results separate from the accepted-candidate pool. Only update `_top_candidates` from `accept_candidate()` after the candidate passes the acceptance rule.

2. File: `noa/unified_agent.py:248`
   Severity: high
   Category: Diff
   Description: `_build_result()` reports `final_score` as `max(self._best_score, self._baseline_score)` even when `_final_eval_top_candidates()` returns no winning held-out candidate. That can claim an improved final score based only on train-side evaluation, even if nothing was committed.
   Suggested fix: Compute `final_score` from committed state only. If final held-out evaluation does not select a winner, keep the baseline score or explicitly re-evaluate the committed workspace on the held-out set before returning results.

3. File: `scripts/run_pubmedqa.py:50`
   Severity: high
   Category: Diff
   Description: The script claims "train/test complete isolation" but loads a single split with `load_pubmedqa(split=data.get("split", "train"), n=total_n)` and then samples both `test_set` and `train_pool` from that same in-memory dataset. That is not a true held-out PubMedQA evaluation and will bias reported benchmark results.
   Suggested fix: Load distinct official train and test splits, or require separate input files for training and held-out evaluation. If only one split exists, label the second partition as validation rather than test and avoid benchmark claims.

4. File: `tests/`
   Severity: high
   Category: Diff
   Description: The regression gate is broken. `pytest -q` fails during collection with 50 errors, including stale imports from removed `noa.planner.*` modules in root tests and missing `dacite` for the vendored `openevolve` suite. The recent unified-agent and PubMedQA changes therefore have no working top-level test protection.
   Suggested fix: Remove or update the legacy planner-era tests, decide whether vendored `openevolve` tests belong in top-level discovery, and either install their dependencies or exclude that tree from the root pytest run.

## Medium

5. File: `target_systems/pubmedqa/`
   Severity: medium
   Category: Diff
   Description: The new PubMedQA target system landed without focused tests. There is no coverage for JSONL loading, adapter wiring, answer extraction, exact-match scoring, or the new end-to-end orchestration path.
   Suggested fix: Add unit tests for `utils.data.load_pubmedqa`, `target_systems/pubmedqa/evaluate.py`, and the adapter contract, plus at least one smoke test for `scripts/run_pubmedqa.py`.

6. File: `utils/llm.py:103`
   Severity: medium
   Category: Diff
   Description: `resolve_model()` discards the caller-supplied model whenever `LLM_PROVIDER` is `vt` or `together`, always returning the provider default. That makes model-selection settings ineffective under those providers.
   Suggested fix: Preserve explicitly requested models when they are already provider-qualified, or map the requested logical model to a provider-specific equivalent instead of always replacing it with a single default.

7. File: `utils/llm.py:114`
   Severity: medium
   Category: Diff
   Description: `_vt_kwargs()` mutates `OPENAI_API_KEY` and `OPENAI_API_BASE` in `os.environ` on every call. Because the process performs concurrent evaluations, one VT-targeted request can leak provider configuration into unrelated requests in the same process.
   Suggested fix: Pass provider credentials and base URLs directly to the client call instead of mutating process-global environment variables, or isolate provider switching in subprocesses.

8. File: `.`
   Severity: medium
   Category: Holistic
   Description: The repository is under-documented for independent agent work. There is no root `README.md`, `AGENTS.md` points to `README.md` and `docs/QUICKSTART.md` even though both are missing, major working directories such as `noa/`, `scripts/`, `target_systems/`, `tests/`, and `configs/` lack local `AGENTS.md` files, and the root `CLAUDE.md` is not symlinked to `AGENTS.md`.
   Suggested fix: Add a root README, restore or remove broken documentation references, add directory-level `AGENTS.md` files for major work areas, and symlink each compatibility `CLAUDE.md` to its corresponding `AGENTS.md`.

9. File: `.env.example:1`
   Severity: medium
   Category: Holistic
   Description: Runtime configuration is not documented or validated. `.env.example` is still a placeholder while the code depends on provider-specific credentials and settings such as `LLM_PROVIDER`, `VT_API_KEY`, `TOGETHER_MODEL`, `LLM_TIMEOUT_SEC`, and `LLM_RPM_LIMIT`. Missing or invalid values will fail late at runtime.
   Suggested fix: Document every required and optional environment variable with defaults and provider requirements, then add startup validation that fails fast with actionable error messages.
